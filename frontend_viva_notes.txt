# DIGITAL WARDROBE — FRONTEND & UI VIVA PREPARATION GUIDE

================================================================================
1. The 30-Second Golden Answer (Memorize This!)
================================================================================

"Sir, we built our frontend using Reflex, which is a reactive full-stack Python framework.

Instead of writing raw JavaScript and separate React code, Reflex lets us define the UI components directly in Python. Under the hood, Reflex compiles our Python code into a production React.js Single-Page Application (SPA) using Tailwind CSS and Radix UI components.

The frontend and backend communicate in real-time over WebSockets. The UI is completely state-driven: whenever a user clicks a button or updates a filter, an Event Handler updates the state on the server, and the UI automatically re-renders only the changed components."


================================================================================
2. How the Frontend is Structured (The 3 Core Pillars)
================================================================================

If the examiner asks: "What is the architecture of your frontend?", explain these 3 concepts:

A. Component-Based Architecture (Like React, but in Python)
Just like in React where you have components, in our project every UI section is a modular Python function returning an rx.Component:
- index.py: The main page layout and conditional router:
    rx.cond(st.WardrobeState.is_logged_in, _dashboard(), login_card())
- header.py: Sticky top navigation bar with tab switching (Overview, Wardrobe, Outfits, Analytics) and the "Add Item" dialog modal.
- checker_tab.py: The Wardrobe inventory view — displays card grids of clothes with category tabs, search, and image upload.
- generator_tab.py: The Outfit Recommender UI — filters by Occasion & Season and displays 3-piece combination cards with compatibility scores.
- history_tab.py: The Analytics view — displays wear history and the Cost-Per-Wear table.

B. Reactive State Management (state.py)
Explain how state works:
- We define a central state class: class WardrobeState(rx.State):
- Any variable that changes in the UI is a State Variable (e.g., active_view, search_query, selected_category).
- When an action happens (e.g. clicking "Mark Clean"):
  1. The UI triggers an Event Handler function in WardrobeState.
  2. The function executes Python logic, modifies the MySQL database via SQLModel/SQLAlchemy.
  3. Reflex sends a JSON diff over a WebSocket connection.
  4. The client's React DOM updates instantly without refreshing the webpage.

C. Styling and Design System
- Radix UI: Used for robust, accessible UI primitives (dialogs, dropdowns, popups, icons).
- Custom CSS (assets/custom.css): Editorial fonts (Fraunces serif for headings, Plus Jakarta Sans for body) and warm cream/ink colors.
- Responsive Layouts: Flexbox and CSS Grid using Reflex primitives like rx.vstack (vertical stack), rx.hstack (horizontal stack), and rx.grid.

3. Step-by-Step Viva Scenarios & Tricky Questions
================================================================================

Q1: "Did you use HTML, CSS, JavaScript or something else?"
Your Answer:
"Sir, we wrote our UI in Python using Reflex's component library (rx.box, rx.button, rx.dialog), but behind the scenes Reflex compiles that Python into standard HTML5, modern CSS (Tailwind), and React JavaScript. So the browser ultimately runs standard HTML/CSS/JS, but we authored and maintain it in Python."

Q2: "How does the frontend talk to the database?"
Your Answer:
"The frontend doesn't talk directly to the database. Instead:
 1. A user interaction (like clicking 'Generate Outfits') emits an event to our WardrobeState on the Python backend.
 2. The state method executes a query against MySQL using SQLModel (or raw SQL with LEAST/GREATEST for the color matrix).
 3. The resulting data is formatted as plain Python dictionaries and updated in the state variable.
 4. Reflex automatically serializes this to JSON and pushes it via WebSockets to the React frontend to display."

Q3: "How does image uploading work in the UI?"
Your Answer:
"We use rx.upload() component. When the user selects a photo of their clothing:
 1. The file is uploaded to the backend server into uploaded_files/.
 2. The server generates a unique filename to prevent collisions.
 3. Only the filename/relative path is saved into the ClothingItem.image_url column in MySQL.
 4. The frontend renders the image dynamically using rx.image(src=...)."

Q4: "What is a Single Page Application (SPA), and is this one?"
Your Answer:
"Yes sir, it is a Single Page Application (SPA). When the user switches between tabs—like from 'Overview' to 'Outfits' or 'Analytics'—the browser does not reload the entire page. Instead, rx.match(WardrobeState.active_view, ...) dynamically swaps only the active tab component in the DOM, making the interface fast and smooth."

Q5: "How is user authentication handled on the frontend?"
Your Answer:
"When a user is not authenticated, the app renders login_card(). Once they input their email and password, our handle_login() event handler validates credentials against the database using PBKDF2-HMAC-SHA256 hash verification. If valid, is_logged_in is flipped to True, triggering a conditional re-render that displays the full dashboard."

4. Summary Table of Frontend Files (Quick Reference)
================================================================================

- digital_wardrobe.py: Root application entry point (app = rx.App()), registers global styles and sets home route /.
- pages/index.py: Main dashboard controller; checks if user is logged in, renders sticky navbar + active tab.
- components/header.py: Sticky top navigation bar with tab buttons & "Add item" modal pop-up.
- components/overview.py: KPI dashboard (Total clothes, Laundry alerts, Neglected items > 60 days, Wardrobe valuation).
- components/checker_tab.py: Wardrobe inventory viewer (Card grid, category filters, item edit/delete, photo uploader).
- components/generator_tab.py: Outfit recommendation page with dropdowns for Occasion & Season, rendering 3-piece matched outfit cards.
- components/history_tab.py: Analytics tab showing wear calendar log and dynamic Cost-Per-Wear table.
- components/theme.py: Central color palette constants (Ink, Cream, Border colors).
- assets/custom.css: Custom typography, fonts, and animation transitions.
